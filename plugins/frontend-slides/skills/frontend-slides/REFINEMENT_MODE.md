# REFINEMENT_MODE.md

딜리버리(Phase 4) 이후의 모든 편집 사이클을 지배하는 **배치 편집 프로토콜**. 목적은 하나 — *1요청 = 1변경* 낭비 패턴을 없애고, 한 번의 왕복으로 변경 리스트 전체를 처리하는 것.

## 언제

Phase 4로 덱을 전달한 뒤 사용자가 보내는 **모든 후속 편집 요청**. 문구 한 줄이든, 슬라이드 재구성이든, 톤/디자인 변경이든 동일하게 이 모드로 처리한다.

## 핵심 규칙

1. **단일 문구 수정도 즉시 적용**
   한 줄 문구 변경 요청도 거부하거나 미루지 않고 바로 Edit. (브라우저 인라인 자동저장 에디터는 로드맵 — 생기면 이런 사소한 수정은 모델 왕복 없이 브라우저에서 처리하도록 라우팅한다.)

2. **배치 처리 — 한 응답에 전부**
   사용자가 리스트(번호형 / 슬라이드별 / 자유형 문단)를 보내면 **모든 항목을 한 응답에서** 처리한다.
   - 서로 독립적인 변경은 **병렬 Edit**로.
   - 리스트 중간에 확인 질문을 끼워넣지 않는다. 정말 모호한 항목만 끝에 모아 한 번 되묻는다.

3. **스코프 고정 — 요청한 것만**
   "하는 김에 X도 고쳤어요"式 확장 금지. 명백한 버그를 발견하면 **고치지 말고 리스트로 보고**만 한다.

4. **리로드 안내 1회**
   응답 끝에 `새로고침해서 확인해주세요` 한 줄. 항목마다 반복하지 않는다.

5. **디자인시스템 변경은 먼저**
   리스트에 "X 디자인 시스템으로 바꿔"가 있으면, [EXTERNAL_DESIGN_SYSTEMS.md](EXTERNAL_DESIGN_SYSTEMS.md)의 경로(단일 교체 또는 멀티테마)로 **먼저** 처리한 뒤 나머지 항목을 이어서 처리한다.

## 처리 순서 (권장)

1. **파싱** — 요청을 원자적 변경 항목으로 분해 (슬라이드 번호 / 대상 요소 / 변경 내용).
2. **분류** — 디자인시스템 변경 → 구조/레이아웃 → 텍스트/톤 → 색/타이포 미세조정.
3. **적용** — 독립 항목 병렬 Edit. 같은 파일·같은 영역이 겹치면 순차.
4. **검증** — 구조/레이아웃을 건드린 슬라이드는 고정 스테이지 규칙 재확인 (16:9 유지, 오버플로/겹침 없음). 필요 시 렌더 스크린샷.
5. **요약 + 리로드 안내** — 처리한 항목을 짧게 요약하고 마지막에 리로드 한 줄.

## 예시

사용자:
```
1. 3번 슬라이드 제목을 "성장 전략"으로
2. 5번의 bullet 4개 → 2개로 줄이고 나머지는 다음 슬라이드로
3. 전체 톤을 좀 더 차분하게 (액센트 채도 낮춰)
4. Notion 디자인 시스템으로 바꿔줘
```
→ 한 응답에서: (4) 먼저 테마 교체 → (2) 슬라이드 분할 → (1) 제목 → (3) 액센트 변수 조정. 병렬 가능한 것은 병렬 Edit. 끝에 "새로고침해서 확인해주세요" 한 줄.

## 안티패턴

- ❌ 항목마다 별도 응답 (왕복 낭비)
- ❌ "1번부터 할까요?" 중간 확인
- ❌ 요청 안 한 개선 끼워넣기
- ❌ 항목마다 "새로고침하세요" 반복
